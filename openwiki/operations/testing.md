# Testing & CI

## Test Suite

The test suite uses `pytest` and is entirely offline — no real Slack API calls are made. Tests run fast (~0.55s for the full suite).

### `tests/test_basic.py` — Core Tests (21 tests)

| Section | Tests | What They Cover |
|---|---|---|
| **Version** | 2 | Assert `__version__ == "0.2.3"` via import and `--version` CLI flag |
| **Catalog integrity** | 5 | Validate `methods.json` has exactly 306 methods, no stale entries, no duplicates; `search_methods()` returns relevant results; `get_method()` returns correct dict |
| **Module imports** | 5 | Assert `usergroups`, `canvas`, `reminders`, `dnd`, `docs` modules import and expose expected functions |
| **CLI argument parsing** | 7 | Subprocess calls to `--help` for each command group; assert returncode 0 and expected subcommands/flags appear |
| **Skills** | 3 | Exactly 33 skill `.md` files exist; each has valid YAML frontmatter (`name:`, `description:`, install marker); all v0.2.0 skills present |
| **Docs cache** | 2 | `_cache_path()` returns expected `.md` path; `_is_cache_fresh()` returns `False` for non-existent files |
| **Config** | 1 | `config show` doesn't crash without a configured profile |

### `tests/test_files_upload.py` — V2 Upload Flow Tests (4 tests)

Uses `monkeypatch` to mock `urllib.request.urlopen` and a `_RecordingSlackClient` to test the V2 file upload flow without network calls:

| Test | What It Verifies |
|---|---|
| `test_call_form_urlencodes_upload_url_external_request` | `files.getUploadURLExternal` sends form-urlencoded POST with correct Content-Type and Authorization header |
| `test_call_form_serializes_complete_upload_files_array` | `files.completeUploadExternal` correctly JSON-serializes the `files` array param |
| `test_upload_request_posts_multipart_file_without_slack_auth` | Direct upload to `files.slack.com` uses `multipart/form-data` with correct headers and **no Authorization header** (pre-signed URL) |
| `test_upload_file_v2_flow_preserves_filename_and_completion_fields` | Full V2 flow: `getUploadURLExternal` → `upload_request` → `completeUploadExternal` — correct param passing for filename, file length, channels, comments |
| `test_upload_file_v2_private_upload_omits_share_fields` | When no channels provided, `completeUploadExternal` omits `channel_id`, `initial_comment`, `thread_ts` (private upload) |

### Testing Patterns

- **No external dependencies**: All tests run without network access, Slack tokens, or API calls.
- **Subprocess for CLI integration**: `test_basic.py` uses `subprocess.run` for `--help` and `--version` checks.
- **Monkeypatch for HTTP unit tests**: `test_files_upload.py` patches `urllib.request.urlopen` with `_FakeHTTPResponse` objects.
- **Catalog as test fixture**: Tests load `methods.json` directly from the package and validate its structure.

### Running Tests

```bash
cd /path/to/slack-toolkit
python -m pytest tests/ -v
```

## CI/CD

### No CI workflows

This repo has **no GitHub Actions workflows**. Tests are run manually (see above). Docs under `openwiki/` are regenerated by scheduled, human-reviewed OpenWiki agent runs (`openwiki code --update --print`, model `z-ai/glm-5.2` via OpenRouter) pushed to review branches — never directly to `main`. The workflow file the openwiki tool self-installs on each run is deleted before staging, per the org Actions-free policy for this pipeline.

## Adding Tests

When adding new CLI commands or modules:

1. Add an import test in `test_basic.py` following the existing pattern (import module, check expected functions exist).
2. Add a `--help` subprocess test for any new command group or subcommand.
3. If the module does HTTP work, add unit tests with `monkeypatch` on `urllib.request.urlopen` following the pattern in `test_files_upload.py`.
4. Update `test_catalog_new_methods_present` if you add methods to the catalog.
5. Update `test_skills_count` if the skill count changes.

Source: `tests/test_basic.py`, `tests/test_files_upload.py`
